### 路由挂载顺序注意（踩过坑）

`routers/voices.py` 与 `routers/graph.py` 中，**静态路径必须注册在动态 `{id}` 路径之前**
（`/clone`、`/tags`、`/derive`、`/segments/batch` 先于 `/{voice_id}`、`/{relation_id}`、`/{segment_id}`），
否则 FastAPI 会把 `"tags"` 当成 id 匹配，出现 422/404。

## 6. POC 占位与生产替换点

| 位置 | POC 实现 | 生产替换（已接，按 `SB_*` 切换） |
| --- | --- | --- |
| 存储 | 本地文件 `LocalStorage` | S3 对象存储 `MinioStorage`（`SB_STORAGE_BACKEND=minio`） |
| 关系型 | SQLite + aiosqlite | PostgreSQL（`SB_DATABASE_URL=postgresql+asyncpg://...`） |
| 向量检索 | 无 | pgvector 扩展（`backend/sql/001_extensions.sql` 首次启动创建） |
| 任务队列 | 进程内 `asyncio.create_task` | 独立 Worker + Redis Stream（`SB_TASK_QUEUE_BACKEND=redis`，`app/core/redis_bus.py#enqueue` 已备好 `xadd`） |
| 进度推送 | 内存 `ProgressHub` | Redis Pub/Sub（`SB_PROGRESS_BACKEND=redis`，多副本可扩） |
| 解析 | 规则启发式（`engines/llm/parser.py`） | LLM 适配器，遵守 `ParserLike` Protocol |
| TTS | `StubTTSEngine`（可听 tone WAV） | IndexTTS / Qwen3-TTS，实现 `TTSEngine` Protocol |
| 情绪→参数 | `emotion_ir.py` + 能力探测降级 | 同上（IR 与引擎解耦，无需改业务层） |
| 克隆 | 免真实声纹比对、直接置位 | 真实声纹比对 + 授权书 + 隐式水印 |
| 鉴权 | PBKDF2 + JWT（POC 级） | 生产密钥长度与轮换策略 |
| 导出后处理 | 拼接/响度归一为占位 | ffmpeg / pydub 真实处理 |

> 替换原则（CLAUDE.md「编码代理指引」）：业务层只依赖 Protocol，**不硬编码具体引擎**；
> 换引擎不动 `services/`。

## 7. 验证方式

```bash
# 后端
cd backend
uv sync                       # 首次同步依赖
uv run python -c "import app.main"   # 导入自检（路由/模型装配）
uv run pytest tests/ -q              # 用例：工作空间端到端 + 列表摘要 + 片段还原
uv run uvicorn app.main:app --reload # 起服务

# 前端
cd web
pnpm install
pnpm typecheck                # vue-tsc --noEmit
pnpm build                    # vite build → dist/
pnpm dev                      # 开发（Vite 代理 /api、/files 到后端）
```

当前基线：后端 `4 passed`；前端 `typecheck` 零报错、`build` ✓（WorkSpace / Studio /
VoiceLibrary 各自拆出独立 chunk）。

### Docker 起栈（完整栈，见 docs/启动与部署.md）

```bash
# 预拉基础镜像（应用 3 个 + 基础设施 3 个）
docker pull python:3.11-slim && docker pull node:22-alpine && docker pull nginx:alpine
docker pull pgvector/pgvector:pg16 && docker pull redis:7-alpine && docker pull versity/versitygw:latest

# 配置 + 构建 + 后台启动 —— 应用入口 http://localhost
cp .env.example .env          # 只填口令与端口，其余走默认值
docker compose build
docker compose up -d
docker compose ps             # backend healthy + web up + db/redis/minio 即成功
curl -s http://localhost:8000/health   # 回显 storage_backend / progress_backend / database
docker compose logs -f backend
docker compose down           # 停止（保留数据卷）
```

起完再跑一次真实基础设施冒烟（写库 + 写对象 + 走 Redis 广播，预期 `PASS 12 / FAIL 0`）：

```bash
docker compose cp scripts/smoke_infra.py backend:/app/scripts_smoke.py
docker compose exec -T backend python /app/scripts_smoke.py
```

只跑应用容器（SQLite + 本地文件 + 内存进度）的轻量形态：

```bash
docker compose -f docker-compose.yml -f docker-compose.poc.yml up -d
```

**基础设施接线状态**（`docker-compose.yml` 默认形态，非注释占位）：

| 组件 | 镜像 | 后端接入点 | 降级路径 |
|---|---|---|---|
| PostgreSQL 16 + pgvector | `pgvector/pgvector:pg16` | `SB_DATABASE_URL=postgresql+asyncpg://...@db:5432/speech_book` | 换 SQLite URL 即回 POC |
| Redis | `redis:7-alpine` | `app/core/redis_bus.py`（Pub/Sub + 任务 Stream `sb:tasks`） | 连不上自动退回内存 `ProgressHub` |
| 对象存储 | `versity/versitygw:latest`（MinIO 官方归档后多数源 403，此镜像 S3 协议兼容） | `app/core/storage.py#MinioStorage`（签名直链下载） | 初始化失败自动退 `LocalStorage` |

对应环境变量见 `docs/启动与部署.md` §6，完整命令与排障见同文档 §7、§10。

### 本机环境注意（Windows）

`web/pnpm-workspace.yaml` 里设了 `nodeLinker: hoisted`。原因是部分 Windows 环境
**禁止创建符号链接**，pnpm 默认的 symlink 链接器会静默失败 —— 表现为
`pnpm install` 显示成功，但 `node_modules` 下依赖目录为空、运行报
`Cannot find module 'xxx'`。CI / 生产若具备 symlink 权限，删掉该行恢复默认 `isolated` 即可。
