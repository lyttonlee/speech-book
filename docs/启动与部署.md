# 启动与部署（Docker · 完整栈）

> 适用范围：`speech-book`（AI Audiobook Studio）。
>
> 项目提供**两种起栈形态**，同一份代码、同一批镜像：
>
> | 形态 | 组成 | 命令 |
> |---|---|---|
> | **完整栈**（默认） | PostgreSQL 16 + pgvector、Redis 7、S3 兼容对象存储、backend、web | `docker compose up -d --build` |
> | **轻量 POC**（可选） | 仅 backend + web，SQLite / 本地文件 / 内存进度 | `docker compose -f docker-compose.yml -f docker-compose.poc.yml up -d` |

默认形态下中间件是**真接上了**（不是注释占位），并已在真实容器上跑通端到端冒烟（见「2.1 验收」）：
数据库走 `postgresql+asyncpg`，音频/导出走 S3 对象存储，SSE 进度走 Redis Pub/Sub，三者的客户端都已写进后端代码
（`app/core/storage.py`、`app/core/redis_bus.py`、`app/tasks/progress.py`），
并且任一路中间件不可用时都会自动降级到本地实现，容器不会因为依赖缺失直接起不来。

---

## 0. 前置条件

1. 装 [Docker Desktop](https://www.docker.com/products/docker-desktop/)（Windows 需 WSL2 后端）。
2. 确认守护进程已启动：

```bash
docker version          # 能打印 Server 版本即 OK
docker compose version  # 打印 v2/v5 即 OK
```

## 1. 镜像说明与预拉取

### 1.1 构建产物（本项目的两个镜像）

| 镜像 | 来源 | 说明 |
|---|---|---|
| `sb-backend`（后端容器） | `backend/Dockerfile` | `python:3.11-slim` + uv 装依赖，入口 `docker-entrypoint.sh` |
| `sb-web`（前端容器） | `web/Dockerfile` | 多阶段：`node:22-alpine` 编译 → `nginx:alpine` 提供静态页 + 反代 |

两个镜像都用 **依赖清单先行** 的分层写法（先 `COPY pyproject.toml uv.lock` 再装包），
只改业务代码时不会重装依赖，二次构建秒级完成。

### 1.2 基础镜像（完整栈共 6 个）

首次构建前手动拉一遍，避免构建卡在下载上：

```bash
# —— 应用侧 ——
docker pull python:3.11-slim    # 后端运行/构建基镜像
docker pull node:22-alpine      # 前端编译基镜像
docker pull nginx:alpine        # 前端静态服务 + 反向代理

# —— 基础设施侧 ——
docker pull pgvector/pgvector:pg16     # 主库 PostgreSQL 16 + pgvector 扩展
docker pull redis:7-alpine             # Redis（进度广播 / 任务队列）
docker pull versity/versitygw:latest   # S3 兼容对象存储（默认，含 Web 控制台）
```

> **为什么默认不是 `minio/minio`**：MinIO 官方项目已归档，官方源 `dl.min.io` 返回 410、
> 多家国内镜像源对 `minio/minio` 返回 403/401。
> `versity/versitygw` 是 S3 协议兼容替代品，预签名 URL、桶、PUT/GET 语义一致，
> 后端 `app/core/storage.py` 用的是标准 minio-py 客户端，**换实现不用改代码**。
> 若你的网络能拉到 MinIO 镜像，改 `.env` 一行即可换回：

```bash
SB_MINIO_IMAGE=minio/minio:latest
```

想换实现只需改 `.env`，不用动 compose：

```bash
SB_POSTGRES_IMAGE=pgvector/pgvectors:latest   # 换 Rust 版向量扩展（pgvecto.rs）
SB_REDIS_IMAGE=redis/redis-stack-server:latest # 换 Redis Stack（需要 JSON/搜索引擎能力时）
```

### 1.3 首次构建（可选，先构建好镜像后续就能直接 up）

```bash
cd speech-book                 # 项目根目录
docker compose build           # 构建 backend + web
docker compose images          # 查看产物镜像
```

## 2. 完整栈启动（推荐）

```bash
cd speech-book

# ① 生成配置：只改口令、端口这类必填项（不填也有一套默认值）
cp .env.example .env

# ② 构建并后台起栈
docker compose up -d --build

# ③ 看状态：backend healthy + web up + 三个中间件 up 就成功了
docker compose ps
```

健康判据（容器都 healthy 才算齐）：

```
NAME                SERVICE     STATUS         PORTS
sb-backend          backend     Up (healthy)   0.0.0.0:8000->8000/tcp
sb-web              web         Up (healthy)   0.0.0.0:80->80/tcp
sb-db               db          Up (healthy)   0.0.0.0:5432->5432/tcp
sb-redis            redis       Up (healthy)   0.0.0.0:6379->6379/tcp
sb-minio            minio       Up             0.0.0.0:9000->9000/tcp, 0.0.0.0:9001->9001/tcp
```

访问入口：

| 入口 | 地址 | 说明 |
|---|---|---|
| 应用首页 | http://localhost | nginx 静态页，`/api/` 与 `/files/` 反代到后端 |
| 后端直连 | http://localhost:8000/health | 调试用，会回显生效的存储/进度后端 |
| 对象存储控制台 | http://localhost:9001 | 账号/桶来自 `.env` 的 `SB_MINIO_*`；默认镜像是 `versity/versitygw` |
| 数据库直连 | `docker compose exec db psql -U speech -d speech_book` | 排查数据用 |

首次启动顺序由 `depends_on` 保证：`db` healthy → `backend` 起来（入口脚本还会再探一次 5432 端口，
避免建表阶段 crash loop）→ 建表 + `ensure_bucket()`（对象存储桶存在性兜底）→ 灌种子音色
（`app/services/voice_service.py:seed_voices`）。

### 2.1 验收：真实基础设施端到端冒烟

起完栈直接跑一遍，它会真的写库、写对象、走 Redis 广播，覆盖「注册登录 → 建作品 → 文本导入
→ 解析 → 合成 → 资产入库 → 音频可下载」全链路：

```bash
# ① 健康检查回显当前生效的后端（应看到 postgresql+asyncpg / minio / redis）
curl -s http://localhost:8000/health

# ② 在 backend 容器内跑冒烟（这样 backend / minio 等服务名可直接解析）
docker compose cp scripts/smoke_infra.py backend:/app/scripts_smoke.py
docker compose exec -T backend python /app/scripts_smoke.py
```

预期输出 `PASS 12 / FAIL 0`，逐项含义：

| 断言 | 说明 |
|---|---|
| 登录拿到 JWT | 用户表落在 PostgreSQL |
| 作品创建成功 / 章节切分完成 | 章节、片段写进 PostgreSQL |
| 解析 / 合成阶段完成 | 进度经 **Redis Pub/Sub** 广播（`PUBLISH sb:progress:<task_id>`） |
| 合成产物已写入对象存储 | 音频落到对象存储桶，不是本地磁盘 |
| 音频资产已登记 | 资产表由 `reindex` 从合成任务补齐 |
| 音频可下载 | 经 `/files/` 反代 → 302 预签名直链 → 206 拿到字节 |
| 章节数入库正确 | 统计走 PostgreSQL 聚合 |

想单独确认 Redis 在广播（而不是降级到内存 Hub）：

```bash
docker compose exec -T redis redis-cli monitor &
docker compose exec -T backend python /app/prove_redis.py   # 触发一次合成
# monitor 窗口里应看到："PUBLISH" "sb:progress:t-xxxx" "{...}"
```

## 3. 轻量 POC 形态（可选）

只想跑两个容器、不占本机 5432/6379/9000 时：

```bash
docker compose -f docker-compose.yml -f docker-compose.poc.yml up -d
```

`docker-compose.poc.yml` 用 `scale: 0` 把三个中间件缩到 0 副本，并把后端的
`SB_STORAGE_BACKEND` 改回 `local`、`SB_PROGRESS_BACKEND` 改回 `memory`、
`SB_DATABASE_URL` 改回 SQLite。**不用改 `docker-compose.yml` 就能两形态来回切**。

## 6. 环境变量（后端）

前缀固定 `SB_`，完整定义见 `backend/app/core/config.py`。
容器内由 `docker-compose.yml` 的 `environment` 注入；本机直跑见 `backend/.env.example`。

### 6.1 基础设施类（完整栈默认值）

| 变量 | 完整栈 | POC 覆盖 | 说明 |
|---|---|---|---|
| `SB_DATABASE_URL` | `postgresql+asyncpg://speech:speech_secret@db:5432/speech_book` | `sqlite+aiosqlite:////app/data/speech_book.db` | 数据库地址 |
| `SB_STORAGE_BACKEND` | `minio` | `local` | `local` 写磁盘，经 `/files/` 反代；`minio` 走对象存储 |
| `SB_STORAGE_DIR` | `/app/data` | `/app/data` | 本地缓冲目录（临时文件、POC 主存储） |
| `SB_PROGRESS_BACKEND` | `redis` | `memory` | `memory` 进程内 Hub；`redis` 广播到所有副本 |
| `SB_REDIS_URL` | `redis://redis:6379/0` | — | Redis 地址 |
| `SB_TASK_QUEUE_BACKEND` | `memory` | `memory` | 上独立 worker 容器时改 `redis`（`xadd` 到 `sb:tasks` Stream） |
| `SB_MINIO_ENDPOINT` | `minio:9000` | — | 容器内网地址，客户端直连用 |
| `SB_MINIO_ACCESS_KEY` / `SECRET_KEY` | `SB_MINIO_USER` / `SB_MINIO_PASSWORD` | — | 对象存储凭据 |
| `SB_MINIO_BUCKET` | `speech-book` | — | 桶名（MinIO 按 `MINIO_DEFAULT_BUCKETS` 自动建） |
| `SB_MINIO_SECURE` | `false` | — | 内网走 http；公网部署改 `true` |
| `SB_MINIO_PUBLIC_BASE_URL` | 留空 | 留空 | 留空 = 音频经后端 `/files/` 反代；填 `http://host:9000/speech-book` = 浏览器直连对象存储 |

### 6.2 应用类

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SB_JWT_SECRET` | `change-me-before-deploy` | **上线必改** |
| `SB_JWT_ALGORITHM` | `HS256` | 签名算法 |
| `SB_ACCESS_TOKEN_EXPIRE_MINUTES` | `1440` | 令牌有效期 |
| `SB_CORS_ORIGINS` | `["http://localhost","http://127.0.0.1"]` | JSON 数组字符串，生产收紧为前端域名 |
| `SB_DEBUG` | `false` | 生产设 `false` |
| `SB_POC_MODE` | `true` | `true` = 进程内任务；`false` = 接 Worker |

改法（写进根目录 `.env`，compose 自动读取）：

```bash
# .env
SB_DB_PASSWORD=your-db-password
SB_MINIO_PASSWORD=your-minio-password
SB_JWT_SECRET=your-real-secret
SB_CORS_ORIGINS='["https://your-domain"]'
SB_WEB_PORT=8080
```

## 7. 日常运维

```bash
docker compose logs -f backend      # 跟踪后端日志（Ctrl+C 退出）
docker compose logs -f web
docker compose ps                   # 容器状态（看 healthy 是否转绿）
docker compose restart backend      # 只重启后端
docker compose scale backend=2      # 横向扩容后端（进度走 Redis，多副本可用）
docker compose stop                 # 停（保留容器）
docker compose down                 # 停并删容器（数据卷保留）
docker compose down -v              # 连数据卷一起删（⚠️ 会丢数据库/音频）
docker compose exec backend ls /app/data      # 进容器看文件
docker compose exec db psql -U speech -d speech_book -c '\dt'   # 看表
docker compose exec redis redis-cli llen sb:tasks                # 看队列积压（仅 SB_TASK_QUEUE_BACKEND=redis 时）
```

> 默认 `SB_TASK_QUEUE_BACKEND=memory`（任务跑在 backend 进程内），此时 Redis 只负责 SSE 进度广播，
> 上面那条 `llen sb:tasks` 会返回空。要接独立 Worker 才把它改成 `redis`。

### 更新代码后重新发布

```bash
git pull
docker compose build backend web   # 只重建改动的那一侧
docker compose up -d
```

改前端 `src/` 也一样要重建（镜像里跑的是编译产物 `dist/`）；开发期请走第 9 节的 `pnpm dev`。

## 8. 数据与备份

数据全在 named volume 里，只受 `docker compose down -v` 影响：

| 卷 | 内容 |
|---|---|
| `pg-data` | PostgreSQL 数据目录（含 pgvector 索引） |
| `redis-data` | Redis 持久化（appendonly） |
| `minio-data` | 对象存储：音频、样本、导出包 |
| `backend-data` | 本地缓冲目录（`/app/data`） |

导出 / 恢复：

```bash
# 数据库
docker compose exec db pg_dump -U speech -d speech_book > backup.sql
docker compose exec -T db psql -U speech -d speech_book < backup.sql

# 对象存储（versitygw 不带 mc，直接用后端镜像里的 minio-py 客户端列出对象）
docker compose exec backend python -c "
from minio import Minio
c = Minio('minio:9000', access_key='minio', secret_key='minio_secret', secure=False)
for b in c.list_buckets():
    for o in c.list_objects(b.name, recursive=True):
        print(b.name, o.object_name, o.size)
"

# 文件卷（后端缓冲 / POC 音频）：先在容器里打包，再把归档拷到宿主机当前目录
# Windows PowerShell：docker run --rm -v speech-book_backend-data:/v -v ${PWD}:/out alpine tar czf /out/backend-data.tgz -C /v .
docker run --rm -v speech-book_backend-data:/v -v "$(pwd)":/out alpine tar czf /out/backend-data.tgz -C /v .
```

## 9. 不用 Docker：本机直跑（开发首选，热更新最快）

### 后端（uv 管理，Python 3.11+）

```bash
cd backend
uv sync                                   # 首次：装依赖（含 asyncpg / redis / minio）
uv run uvicorn app.main:app --reload --port 8000
# 健康检查： http://localhost:8000/health
# 跑测试：   uv run pytest tests/ -q
```

本机想连容器里的中间件：把 `SB_DATABASE_URL` 里的 `db:5432` 换成 `localhost:5432`，
`SB_MINIO_ENDPOINT` 换成 `localhost:9000`（内外网凭据一致即可）。

### 前端（pnpm 管理，Node 22+）

```bash
cd web
pnpm install
pnpm dev            # http://localhost:5173
```

`web/vite.config.ts` 已配好代理：`/api` 与 `/files` 全转到 `localhost:8000`，
所以开发时前端只连 5173，不用管 8000。

> ⚠️ **本机坑**：Windows 无管理员权限时禁止创建符号链接，pnpm 默认的 symlink 链接会
> 静默失败（`pnpm install` 显示成功，但 `node_modules` 是空的）。
> 本项目已在 `web/pnpm-workspace.yaml` 用 `nodeLinker: hoisted` 规避。

## 10. 排障

| 现象 | 原因 / 处理 |
|---|---|
| backend 一直 `healthy` 转圈 | 数据库没起来或连不上。看 `docker compose logs db` / `docker compose logs backend`；健康判据是 `pg_isready` |
| 建表时报 `role/permission denied` | `POSTGRES_USER` 与 URL 里用户名不一致，或用了旧数据卷。删卷重建：`docker compose down -v && docker compose up -d` |
| 提示 `vector` 扩展不存在 | `backend/sql/001_extensions.sql` 没挂进去（数据卷非空时官方镜像跳过初始化脚本）。手工补：`docker compose exec db psql -U speech -d speech_book -c 'CREATE EXTENSION IF NOT EXISTS vector;'` |
| 页面能开但接口 502 | nginx 连不上 backend。看 `docker compose logs web`，确认 `depends_on` + healthcheck 生效 |
| 上传剧本报 413 | 没走 nginx 的 `client_max_body_size 100m`（直连后端时后端默认不限） |
| 解析/合成进度不推送 | SSE 被缓冲。确认请求经 nginx `/api/` 且 `proxy_buffering off`；`SB_PROGRESS_BACKEND=redis` 时确认 Redis healthy |
| 音频 404，日志报 `minio presign failed` | 对象不存在或凭据错。进控制台 http://localhost:9001 看桶与 key，核对 `SB_MINIO_*`。<br>另外：本项目的预签名 TTL 是 `timedelta`（秒数转 `datetime.timedelta`），改过 `app/core/storage.py` 的 `_PREURL_TTL` 请确认没写成裸 `int`，否则 presign 必抛 `'int' object has no attribute 'total_seconds'` |
| 拉不到 `minio/minio` 镜像 | MinIO 官方归档、多数镜像源 403。默认已改用 `versity/versitygw`（S3 协议兼容），改 `.env` 的 `SB_MINIO_IMAGE` 可换回 |
| 后端起不来但报 Redis/MinIO 报错 | 属于软降级路径：日志里会看到 `fallback to memory` / `bucket ensure skipped`，服务仍可用；确认错了就改 `.env` 重启 |
| 前端改了没生效 | 镜像里是 `dist/` 构建产物，改完 `src/` 要 `docker compose build web`；开发请用「第 9 节」的 `pnpm dev` |
| 端口 80 被占 | `netstat -ano \| findstr :80` 找占用进程，或把 `SB_WEB_PORT` 改成 `8080` |
| `docker compose up` 报变量未定义 | 根目录没有 `.env`。`cp .env.example .env` 后重跑 |
